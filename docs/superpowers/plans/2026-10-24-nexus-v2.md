# NEXUS IDE v2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Friendly dark redesign with a VS Code-feeling editor, clean console, branding/credits, phone polish, and Arduino (Verify/Upload/Serial) on Windows.

**Architecture:** Keep the existing `core/` (engine) + `ui/` (widgets, screens) split. New pure-Dart logic (`code_format.dart`, Arduino port parsing) lives in `core/` with unit tests; widgets stay thin. Arduino reuses `runTool` for compile, upload and the serial monitor (`arduino-cli monitor`), so no serial plugin.

**Tech Stack:** Flutter 3.47, flutter_code_editor 0.3.5, arduino-cli (portable) + arduino:avr core, flutter_launcher_icons (dev).

**Spec:** `docs/superpowers/specs/2026-10-24-nexus-v2-design.md`

## Global Constraints
- Credit text exactly: `Developed by Logan M. Panucat · Developer`.
- Home header text: `NEXUS IDE` / `CTU Naga Extension Campus · works offline`.
- Tile order: C, Arduino, Python, Java, C#. No year-level labels.
- Run label: `▶ Run` on Android, `▶ Run (F5)` on desktop.
- Format shortcut on desktop: Shift+Alt+F. Indent unit: 4 spaces.
- Console status lines: `● Compiling…`, `✓ Compiled`, `▶ Running`; failing step prints `Command: <tool args>`.
- Arduino boards: Uno `arduino:avr:uno`, Nano `arduino:avr:nano`, Nano (old bootloader) `arduino:avr:nano:cpu=atmega328old`, Mega `arduino:avr:mega`. Default baud 9600.
- No new runtime dependencies. Project is not a git repo: no commit steps.

## Review Focus
- Enter typed via phone keyboard (IME commits word + newline together) must still auto-indent → test `smartNewline` with a multi-char insert ending in `\n`.
- Braces inside strings/comments (`printf("{")`, `// }`) must not change indent → formatter test.
- Upload pressed with no board / no port selected → clear message, no process started → test `uploadArgs` returns null message path.
- Serial monitor running when Upload pressed → monitor killed first (RunSession.stop before run) → covered by existing stop-before-run; verify manually.
- Python file formatted → indentation untouched → formatter test.

### Task 1: Formatter + smart newline (pure Dart)
**Files:** Create `lib/core/code_format.dart`; Test `test/code_format_test.dart`
**Interfaces — Produces:**
- `String formatCode(String text, {required bool braces})` — braces=true: re-indent by `{}` depth (ignoring strings, chars, `//` and `/* */` comments; a line starting with `}` dedents first; `case x:`/`default:` stay at switch depth +1), trim trailing spaces, collapse 3+ blank lines to 1, end with one `\n`. braces=false: only trim + collapse.
- `TextEditingValue? smartNewline(TextEditingValue oldV, TextEditingValue newV)` — if newV = oldV with an inserted run ending in `\n` at the caret (diff by common prefix/suffix), append the previous line's leading spaces (+4 if that line ends with `{` or `:`; if the char after caret is `}`, put it on its own dedented line). Else null.
- [ ] Tests: `formatCode` on a flat C main → 4-space nested output; `printf("{")` and `// }` don't change depth; Python input keeps indents; `smartNewline` with `"int main() {"`+`"\n"` → caret line has 4 spaces; IME-style insert `"foo\n"` also indents; between `{}` → `{\n    \n}`.
- [ ] Run `flutter test test/code_format_test.dart` → fail, implement, → pass.
